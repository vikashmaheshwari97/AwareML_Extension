Resume ended workers while another worker continues

The new helper schedules only unstarted tasks from selected source workers that Slurm reports as completed with exit code 0:0 and whose final summaries show a normal allocation boundary or completed shard. Every other source worker's complete task list remains reserved, including its future tasks. The active worker is neither cancelled nor reassigned.

For source array 2999498, workers 0, 1 and 3 have 33, 35 and 271 remaining tasks: 339 in total. Three new workers can process those tasks alongside source worker 2. The helper checks the source accounting, running jobs, task histories and maximum of four concurrent exclusive AwareML workers. Persistent per-source-shard claims prevent overlapping resume plans. Unsuccessful or interrupted attempts require review and are not automatically retried.

Allocation lookup correction

The original launcher's allocation lookup uses SLURM_JOB_ID. For an array placeholder whose numeric ID equals the parent array ID, Slurm can return multiple array-element records. Merging those records can select another worker's elapsed time and incorrectly produce an immediate allocation boundary. The new helper queries the exact SLURM_ARRAY_JOB_ID_SLURM_ARRAY_TASK_ID, requires one matching record and reads that element's actual TimeLimit and RunTime. A synthetic regression test reproduces the original multi-record failure. The zero-second worker summary alone does not prove its exact scheduler response.
