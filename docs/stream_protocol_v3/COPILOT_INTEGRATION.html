Dataset-aware recommendation in Copilot

The revised Meta-Recommender is integrated into the existing Copilot Workspace. There is no separate version-labelled sidebar page. The three evidence paths retain their familiar names and use explicit readiness states.

PathSource and behaviour
01 · Goal interpretationThe existing LLaMA objective interpreter identifies Accuracy, Runtime, Energy and CO₂ priorities. Human review and separate drift, fairness and explainability requirements remain available. Interpretation works while recommender training is pending. Learned framework rankings require the current trained bundle and an observed labeled prefix.
02 · Historical preference priorUses development aggregates from the same verified bundle as the learned models. Each dataset/framework outcome is aggregated across seeds first. Preference utility is normalized within each dataset, then averaged across development datasets. It is global historical guidance, not a dataset-specific model or a probability. External outcomes are excluded.
03 · Dataset-aware ML RecommenderCalls the revised prefix-only service. Up to the first 1,000 labeled observations supply the profile. Full-stream length, dataset family, source type and drift type are not deployment inputs. Objective weights rank the active portfolio. The LLM can explain the already-produced ranking but cannot choose or reorder frameworks.

Evidence counts and pending states

The old fixed counters (705 runs, three seeds, 235 training rows and a completed 31-dataset external evaluation) are removed from the active Copilot paths. Counts come from verified development aggregates and the bundle manifest. While no trained bundle is installed, the historical and dataset-aware paths show training pending. No legacy model is silently substituted.

For complete 47-dataset evidence, the primary four-framework portfolio would have 188 dataset–framework training rows and 940 underlying runs at five seeds. The extended five-framework portfolio would have 235 rows and 1,175 runs. These are explanatory arithmetic examples, not claims that training has finished. The actual dashboard displays the bundle's counts, including any explicitly documented complete-case exclusions.

ChaCha, if present in an extended bundle, is labelled ChaCha-OVR as a supplementary AwareML classification adaptation. The primary bundle remains the default.

Training and evaluation provenance

Bundle hashes, required objective models, prefix-only features, development-only rows, complete framework coverage, seed coverage and training library compatibility are checked before readiness. Invalid evidence blocks inference. Human corrections rerank the same prefix with the current models and clear prior approval. Old Copilot proposals are invalidated when the model or observed dataset prefix changes.

Nested LODO and external reports are displayed only when their evaluation metadata links to the exact active bundle and the report files pass their hashes. A missing report is shown as pending; the old 91% result is not transferred to the revised experiment. External datasets that have been evaluated before are not described as newly untouched tests.

Install and use

git switch upgrade/stream-protocol-v3
git pull --ff-only
python -m pytest tests/test_copilot_current_protocol.py tests/test_protocol_v3.py -q
python -m streamlit run app.py

On Windows use .\.venv\Scripts\python.exe in place of python. The default bundle directory is artifacts/recommender_v3/primary_prefix. After benchmark validation and training, copy the complete bundle from the measurement/training host to that directory. It must include its manifest, models, development aggregates and training collection. Do not copy only the joblib files.

An administrator can select another validated prefix-only bundle with AWAREML_RECOMMENDER_V3_BUNDLE. Evaluation directories default to sibling directories named primary_prefix_development_evaluation and primary_prefix_external_evaluation; explicit alternatives can be supplied through AWAREML_V3_DEVELOPMENT_EVALUATION and AWAREML_V3_EXTERNAL_EVALUATION.

Research execution remains separate

This update changes the dashboard and its evidence bridge. It does not modify frozen framework, worker, profile, measurement, training or batch-launcher code. The code-fingerprint inputs used by the running campaign remain byte-identical. It does not submit, cancel, retrain or create experimental benchmark results.

Scientific benchmark outcomes retain the common sample cap and safety watchdog. Interactive Run Studio settings are labelled separately and are not represented as the protocol used to train the predictions. The old V2 services, frozen study materials and study result files remain intact for historical reproduction.

Energy and CO₂

The UI does not change how energy or CO₂ are obtained. Current Artemis CPU-load and RAM values remain CodeCarbon estimates, and CO₂ remains derived using the configured country factor. Predicted values inherit the measurement scope and hardware of their training outcomes. With a fixed carbon intensity, Energy and CO₂ are correlated representations of the same signal; the UI discloses this when interpreting priorities.
